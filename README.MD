# Service Desk Bot

Telegram-бот для создания и обработки заявок на техническую поддержку.

Учебный проект на Python с асинхронной обработкой сообщений, PostgreSQL и ролевой системой доступа.

## Функциональность

### Пользователь

- Регистрация при первом запуске через `/start`.
- Создание заявки с помощью пошаговой формы (FSM).
- Выбор категории, ввод названия и описания проблемы.
- Проверка данных, возврат к предыдущему шагу и отмена.
- Просмотр активных заявок и их статусов.
- Автоматические уведомления об изменении статуса.

### Администратор

- Вход в административный режим через `/admin`.
- Проверка прав администратора через PostgreSQL.
- Просмотр новых заявок и заявок в работе.
- Получение информации об авторе обращения.
- Взятие заявки в работу и её закрытие.
- Отдельная клавиатура с выходом из административного режима.

### Статусы заявок

| Статус | Описание |
|---|---|
| `new` | Новая заявка |
| `in_progress` | Заявка в работе |
| `closed` | Заявка закрыта |

Закрытые заявки сохраняются в базе данных, но не отображаются в списках активных обращений.

## Технологии

- **Python** — основной язык разработки.
- **aiogram 3** — асинхронный Telegram Bot API.
- **PostgreSQL** — реляционная база данных.
- **SQLAlchemy 2.0** — ORM и асинхронные запросы.
- **asyncpg** — асинхронный драйвер PostgreSQL.
- **Alembic** — управление миграциями БД.
- **FSM** — управление состояниями пользователя.
- **Logging** — журналирование работы приложения.

## Установка и запуск

### 1. Клонирование репозитория

```bash
git clone https://github.com/extaezy/Service-Desk.git
cd Service-Desk
```

### 2. Создание виртуального окружения

Windows PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

### 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 4. Настройка окружения

Создайте базу данных PostgreSQL.

В корне проекта создайте файл `.env`:

```dotenv
BOT_TOKEN=your_telegram_bot_token
DATABASE_URL=postgresql+asyncpg://user:password@localhost:5432/service_desk
```

Укажите свой токен Telegram-бота и параметры подключения к PostgreSQL.

### 5. Применение миграций

```bash
alembic upgrade head
```

### 6. Запуск бота

```bash
python main.py
```

## Назначение администратора

После регистрации пользователя через `/start` его роль можно изменить в PostgreSQL:

```sql
UPDATE users
SET role = 'admin'
WHERE telegram_user_id = 123456789;
```

Замена необходима для определения администратора, который в будущем будет получать заявки.

Для входа в административный режим используется команда `/admin`.

## Архитектура базы данных

Используются две основные таблицы:

**users** — данные Telegram-пользователей, их идентификаторы и роли.

**tickets** — заявки с описанием проблемы, категорией, статусом и ссылкой на пользователя через внешний ключ `user_id`.

Между таблицами установлена связь **one-to-many**: один пользователь может создать несколько заявок.

## Особенности реализации

- Асинхронная работа с Telegram и PostgreSQL.
- Разделение обработчиков, моделей и запросов к базе данных.
- Использование SQLAlchemy ORM.
- Управление схемой базы через Alembic.
- Разграничение пользовательского и административного режимов.
- Условное обновление статусов для предотвращения повторной обработки заявки.
- Обработка ошибок и логирование.
